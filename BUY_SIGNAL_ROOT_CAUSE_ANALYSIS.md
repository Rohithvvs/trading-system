# BUY Signal Root Cause Analysis

**Date:** 2026-07-23  
**Symptom:** Scanner runs successfully, produces WATCH / REJECT / Favorites, but **BUY Ideas = 0** for multiple days.  
**Status:** Root cause identified and fixed (strategy-preserving; thresholds not blindly lowered).

---

## Executive Summary

BUY signals were being **generated by the recommendation engine**, then **systematically downgraded to WATCH** by the Strict BUY Gate because production candle data from **`CANDLE_CACHE_DB`** was incorrectly flagged as **`mock_warning=true`**.

On warm-cache production runs (the normal path after history is stored), **every symbol** carries `source=CANDLE_CACHE_DB`. The gate required `not mock_warning`, so **no BUY could survive**.

A secondary score-mapping bug mapped **neutral fundamental (and sentiment) scores of `0.0` to 0/100 instead of 50/100**, which reduced composite scores and made it harder to reach the BUY threshold of **72**. That bug was also fixed.

**Proof (simulated production path):**

| Stage | Score / Action |
|-------|----------------|
| Pre-gate (strong tech + backtest) | **BUY 77.5** |
| Post-gate (fixed `CANDLE_CACHE_DB`) | **BUY** |
| Post-gate (old `mock_warning=true` for cache) | **WATCH** (BUY wiped) |

## Task 1 — Complete Scanner Flow (one stock)

```
Universe (stocks_master / NIFTY500)
  → ScreenerService: OHLCV load (FYERS or CANDLE_CACHE_DB)
  → Data validation (min candles, quality flags)
  → Trend / condition filters (screener matched set)
  → Candidate selection (top shortlist)
  → OrchestratorAgent.run_full / _analyze_symbol_post_bulk
      → Technical analysis (bulk)
      → News / sentiment
      → Fundamental analysis
      → Backtest
      → RecommendationService.build
          → Dynamic weights
          → Composite score
          → Initial label: score≥72 BUY | ≥55 WATCH | else REJECT
          → FEAT-004 regime overlay (if enabled; default OFF)
          → FEAT-007 sector RS overlay (if enabled; default OFF)
          → Trade plan (entry / SL / targets / R:R)
      → Strict BUY Gate (_enforce_strict_buy_gate)   ← BUG LIVED HERE
      → Challenger (sector + market permission) — shadow/compare; production BUY uses gated recommendation
  → Rank BUY / WATCH
  → Persist scan snapshot + API response
  → Frontend: buy_candidate_symbols → "BUY ideas"
```

### Label decision order (production)

1. Composite score → initial action  
2. FEAT-004 / FEAT-007 (defaults **disabled**)  
3. **Strict BUY Gate** (can only **downgrade BUY → WATCH**)  
4. Challenger market/sector downgrades (stored separately; shortlist uses **production** `recommendation.action`)

## Task 2 — Why WATCH Was Never Promoted to BUY

For a typical warm-cache symbol (e.g. **EICHERMOT-EQ** path):

| Check | Result |
|-------|--------|
| Data valid | ✓ |
| Trend / screener match | ✓ (favorites / shortlist) |
| AI / recommendation ran | ✓ |
| Trade plan generated | ✓ |
| Composite may reach BUY | ✓ (when tech/backtest strong enough) |
| **Strict BUY Gate** | **✗** |

**Exact rule that failed (pre-fix):**

```text
strong_live_data =
    (not mock_warning)
    AND minimum_swing_candles_met
    AND source in {FYERS_PRIMARY, CANDLE_CACHE_DB}

mock_warning = (source != "FYERS_PRIMARY")   # BUG
```

When `source = CANDLE_CACHE_DB`:

- `mock_warning = True`  ← **incorrect**
- `strong_live_data = False`
- Gate: **BUY → WATCH**

Logged as:

```text
STRICT BUY GATE DOWNGRADE | ... | downgraded_to=WATCH | data_source=CANDLE_CACHE_DB | mock_warning=True
```

Additional gate rules (still intentional; not removed):

| Rule | Requirement |
|------|-------------|
| Technical | best technical score ≥ **75** |
| Execution | trade plan R:R ≥ **1.25** |
| Candles | ≥ **220** swing candles |
| Source | FYERS_PRIMARY or CANDLE_CACHE_DB (trusted) |

After the fix, only true mock/untrusted data fails the live-data leg.

## Task 3 — Recommendation Engine Audit (every path that blocks BUY)

### A. Initial label (`recommendation_service.py`)

| Condition | Action |
|-----------|--------|
| `score >= 72` | BUY |
| `score >= 55` | WATCH |
| else | REJECT |

Composite (baseline, breadth not production):

```text
score = tech*tech_wt + backtest*bt_wt + news*news_wt + fund*fund_wt
```

Default weights: tech 0.50, fund 0.25, backtest 0.25, news 0.0  
(Catalyst regime raises news/fund when volume×3 or |sentiment|≥0.75.)

### B. FEAT-004 Market Regime Overlay

- Settings default: `feat004_enabled=False`  
- When ACTIVE: can adjust score and downgrade BUY under CAU/DEF regimes  
- **Not the multi-day zero-BUY cause** while disabled

### C. FEAT-007 Sector RS Overlay

- Settings default: `feat007_enabled=False`  
- When ACTIVE: WEAK sector can downgrade BUY; STRENGTH cap can prevent WATCH→BUY  
- **Not the multi-day zero-BUY cause** while disabled

### D. Strict BUY Gate (`orchestrator_agent._enforce_strict_buy_gate`)

- Only runs when action is already BUY  
- Downgrades to WATCH if live-data / technical / R:R checks fail  
- **Primary production killer (this incident)**

### E. Market permission / sector challenger

- Can set challenger action to WATCH when `new_entry_allowed=False` or weak sector  
- Shortlist BUY count uses **production** `recommendation`, not challenger  
- Still relevant for UI that surfaces challenger separately

### F. Config / feature flags searched

| Flag / pattern | Result |
|----------------|--------|
| WATCH_ONLY / BUY_DISABLED / STRICT_MODE / SAFE_MODE | **Not found** as env kill-switches |
| SHADOW_ONLY / PROMOTION_DISABLED | Shadow hooks exist; do not strip production BUY |
| FEAT004 / FEAT007 | Default **off** |
| FEAT008 | Execution model for backtests; not a BUY label kill-switch |

## Task 4 — Compare With Last Working Behavior

| Area | Working intent | Broken behavior |
|------|----------------|-----------------|
| `mock_warning` | Only true for **MOCK_FALLBACK** (historical) | `source != FYERS_PRIMARY` → true for **CANDLE_CACHE_DB** |
| Strict gate sources | Live FYERS data | Allowed CANDLE_CACHE_DB later, but still required `not mock_warning` → **self-contradiction** |
| Fundamental raw score | Neutral should be mid-scale | `fundamental_score * 100` with score in **[-1,1]** → neutral **0** points (25% weight drag) |
| Sentiment raw score | Neutral mid-scale | `sentiment_score * 100` with score in **[-1,1]** → same class of bug under catalyst weights |
| Trade plan | Structure-based R:R | Pure avg-range multiples → near-identical R:R across names (improved with swing high/low structure) |
| Thresholds | BUY 72 / gate tech 75 / R:R 1.25 | Unchanged by fix (strategy preserved) |

Git history shows `mock_warning` evolved from:

```python
mock_warning = self._data_source_label() == "MOCK_FALLBACK"
```

to:

```python
mock_warning = primary_source != "FYERS_PRIMARY"  # regression
```

## Task 7 — Risk:Reward Investigation

**Location:** `RecommendationService._build_trade_plans`

- Entry: near last close ± fraction of recent average range  
- Stop: min(entry-based stop, recent swing low − buffer) for longs  
- Target1: max(entry-based target, recent swing high + buffer)  
- R:R = `|target1 − entry_mid| / |entry_mid − stop|`  

**Why R:R looked similar:** older formula used only avg-range multiples → nearly constant ratio (~1.3–2.3).  

**Status:** Structure-aware highs/lows already applied in working tree; R:R is **not hardcoded** and is not the primary zero-BUY cause (gate only needs ≥ 1.25).

## Task 9 — Root Cause (issues list)

### Issue 1 — Primary: `mock_warning` regression (Strict BUY Gate)

| Field | Detail |
|-------|--------|
| **Problem** | `CANDLE_CACHE_DB` treated as mock → `strong_live_data=false` always on warm cache |
| **Evidence** | Gate formula; git history; reproduction: BUY 77.5 → WATCH with old flag, BUY with fix |
| **Files** | `backend/app/agents/orchestrator_agent.py` |
| **Functions** | `_data_quality_payload`, `_enforce_strict_buy_gate` |
| **Impact** | **All production BUY candidates downgraded to WATCH** |
| **Fix** | Trusted sources = `{FYERS_PRIMARY, CANDLE_CACHE_DB}`; `mock_warning = source not in trusted`; promote untagged real candles (`unknown`/`NONE`) to `CANDLE_CACHE_DB`; detailed failed-check logging |

### Issue 2 — Secondary: Neutral fund/sentiment score mapping

| Field | Detail |
|-------|--------|
| **Problem** | `score * 100` on [-1,1] maps neutral 0 → 0 points (25% weight ≈ −12.5 composite vs true neutral) |
| **Evidence** | `FundamentalAnalysisAgent` documents [-1,1]; unit test `test_fundamental_neutral_score_mapping` |
| **Files** | `backend/app/services/recommendation_service.py` |
| **Functions** | `build` |
| **Impact** | Fewer names reach score ≥ 72 even before the gate |
| **Fix** | Map with `(x + 1) / 2 * 100` for fund and sentiment |

### Issue 3 — Incomplete prior patch

| Field | Detail |
|-------|--------|
| **Problem** | Gate allowed `CANDLE_CACHE_DB` in source set but still required `not mock_warning` |
| **Impact** | Partial fix never restored BUY |
| **Fix** | Align mock_warning with trusted sources |

1. Composite score ≥ 72
