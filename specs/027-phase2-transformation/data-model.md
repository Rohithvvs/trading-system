## 1. Schema Overview & Entity Relationship Diagram

The Personal AI Trading Research Platform relies on a simplified relational & time-series database structure. Multi-tenant user tables (`users`, `user_sessions`, `user_profiles`, `otps`, `devices`, `audit_logs`) have been removed. All persistent user-scoped entities link directly to the static application owner ID (`00000000-0000-0000-0000-000000000001`).

```
[ ApplicationOwnerContext ] (Static UUID: 00000000-0000-0000-0000-000000000001)
         │
         ├──► [ PaperTradingAccount ] ──► [ PaperPosition ]
         │                                   └──► [ PaperOrder ]
         │
         └──► [ BrokerToken / FyersToken ]

[ Market Data & AI Pipeline ] (Independent Domain)
  ├── [ StockCandle ] (Time-series pricing)
  ├── [ ScanSnapshot ] (Scanner outputs & indicator values)
  └── [ RecommendationRecord ] (AI scoring & signal rationale)
```

## 2. Table Classifications & Specifications

### 2.1 Preserved Core Data Tables (100% Unchanged Schema)

#### A. `stock_candles`
* **Purpose**: Primary OHLCV pricing storage for scanned market symbols.
* **Key Columns**: `id`, `symbol`, `timeframe`, `timestamp`, `open`, `high`, `low`, `close`, `volume`.
* **Modification**: None.

#### B. `scan_snapshots`
* **Purpose**: Stores historical market scanner execution snapshots and calculated indicator values.
* **Key Columns**: `id`, `scan_timestamp`, `symbol`, `close_price`, `ema50`, `ema200`, `rsi`, `macd`, `supertrend_signal`, `score`.
* **Modification**: None.

#### C. `recommendation_records`
* **Purpose**: Persists output generated by the Recommendation Engine and AI Trading Agents.
* **Key Columns**: `id`, `symbol`, `signal_type` (BUY/SELL), `conviction_score`, `target_price`, `stop_loss`, `ai_rationale`, `created_at`.
* **Modification**: None.

---

### 2.2 Modified Single-Owner Tables

#### A. `paper_trading_accounts`
* **Purpose**: Primary paper trading balance and margin account.
* **Modified Foreign Key**: Foreign key constraint `fk_paper_trading_accounts_user_id` to `users.id` dropped.
* **Columns**:
  * `id` (UUID, Primary Key)
  * `user_id` (UUID, Default: `'00000000-0000-0000-0000-000000000001'`)
  * `initial_balance` (Numeric, e.g., 1,000,000.00)
  * `current_balance` (Numeric)
  * `realized_pnl` (Numeric)
  * `unrealized_pnl` (Numeric)
  * `updated_at` (Timestamp)

#### B. `broker_tokens`
* **Purpose**: Encrypted storage for broker credentials (FYERS Client ID, Secret Key, Access Token).
* **Modified Foreign Key**: Foreign key constraint `fk_broker_tokens_user_id` to `users.id` dropped.
* **Columns**:
  * `id` (UUID, Primary Key)
  * `user_id` (UUID, Default: `'00000000-0000-0000-0000-000000000001'`)
  * `broker_name` (String, e.g., 'fyers')
  * `encrypted_access_token` (Text, Fernet encrypted)
  * `expires_at` (Timestamp)
  * `updated_at` (Timestamp)

## 3. Migration Integrity & Validation

1. **Static Owner Backfill**: Ensures existing `paper_trading_accounts` and `broker_tokens` rows contain `user_id = '00000000-0000-0000-0000-000000000001'`.
2. **Schema Synchronization**: `alembic upgrade head` validates no orphaned foreign key constraints remain pointing to deleted `users` table.
